How this works

The wave calculation

There is no wave buoy anywhere in these waters, so wave height is calculated from forecast wind and each leg's fetch using JONSWAP fetch-limited growth:

g·Hs/U² = 0.0016·√(g·F/U²)      g·Tp/U = 0.286·(g·F/U²)^⅓

Valid here because no ocean swell reaches inside Haro Strait — everything you meet is locally generated wind sea, which is exactly what this law describes.

By hand: Hs ≈ wind(kn) × √fetch(km) / 120. Since fetch is fixed per leg, that's one divisor each — Sidney Channel in a southeasterly is wind ÷ 20, Swanson ÷ 24, Ganges approach ÷ 28, Satellite ÷ 31, Colburne ÷ 38, Sidney Channel in a northwesterly ÷ 49.

Seas need time to build. The formula gives the fully developed sea; reaching it takes 4–6 hours over Haro Strait fetch, about 2 in the sheltered passages. A southeasterly that came up an hour ago has made roughly a third of the table value.

Wind against current, and why rips form

On an opposing current a wave shortens and steepens:

c/c0 = ½(1 + √(1 + 4U/c0))
H/H0 = 2 / [(1 + √(1+4U/c0))·(1+4U/c0)^¼]      c0 = 1.56·T

That height ratio diverges at U = −c0/4 — the blocking limit, where the wave cannot propagate and breaks. That is what a tide rip is.

Same wind, same water, 77% more wave height depending only on tidal phase. In the last row the height falls because the sea has broken down into short steep chop. That is worse, not better, and the page says so rather than letting a smaller number read as improvement.

Tuning it to your boat

Everything lives in the <script> block at the top of this file. No build step, no dependencies — edit and commit.

  • fetch (inside each leg) — the biggest lever. Open-water km to the nearest upwind land, per sector, for the direction wind blows from. These are chart estimates; if a leg reads wrong, fix these first.
  • LIMITS — the green/yellow/red bands. Start conservative, loosen slowly.
  • BOAT.cruiseChop — used for transit and fuel once Hs exceeds chopThreshold. Budgeting the slow number stops you pushing a marginal call because you're running late.
  • floodSet — true bearing the flood sets on that leg; drives the wind-against-current test.
  • peakKn — scales the derived current.

Keep a log. After each trip note what the page said and how the boat felt. A season of that beats any default here.

Where the forecast comes from

Environment Canada retired the marine feed this page used to read. The bulletins are still published, but on the MSC Datamart — a server built for programs rather than browsers. Two things make that awkward to read from a phone: the files sit in folders named by the hour and those folders are deleted as the day rolls over, and a browser may refuse to read another site's data at all.

So a scheduled job fetches it instead. scripts/fetch_bulletin.py runs hourly on GitHub, pulls Haro Strait, Juan de Fuca and Strait of Georgia, and commits data/bulletin.json into this repo. The page reads that from its own address, where nothing can block it.

The old relay chain is still in the file as a fallback, for a fresh clone where the job hasn't run yet. If the stored copy goes more than about seven hours old, the page tries the relays again before trusting it.

Two things the fetcher does deliberately:

  • It picks the sub-area you actually boat in. The Juan de Fuca file covers both entrances; taking the wrong one could hand you the west entrance's 35 knots on a day the east entrance is doing 15.
  • It leaves air temperature out of the forecast text. The page reads every number in that text as a wind speed, so “air temperature 22” would be read as 22 knots and could turn a fine day red. Temperature is stored separately.

If the job stops running, the page keeps working and shows you how old the stored copy is. The Forecast wind box remains the manual override throughout.

If tides won't load

The page asks the Canadian Hydrographic Service for tides directly. Some browsers block that (CHS doesn't send the header that permits it). If you see the "tides unavailable" warning every time, add two files to this repo and GitHub will fetch the data for you nightly.

1. scripts/fetch_tides.py — a short script that pulls 8 days of predictions for Sidney and Active Pass and writes data/tides.json. The page picks that file up automatically.

2. .github/workflows/update.yml:

name: Refresh tides
on:
  schedule: [{ cron: "20 11 * * *" }]
  workflow_dispatch:
permissions: { contents: write }
jobs:
  refresh:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: python scripts/fetch_tides.py
      - run: |
          git config user.name github-actions
          git config user.email actions@github.com
          git add data/tides.json
          git diff --staged --quiet || (git commit -m "tides" && git push)

Then set Settings → Actions → General → Workflow permissions to Read and write. Until you do, wind and waves still work — you just lose currents and slack.

Limits worth knowing
  • Currents are derived from the rate of change of the tide curve, not published current tables. Slack timing is about right; the rate is indicative. For a narrow pass — Active Pass, Porlier, Pender Canal — use the official tables.
  • Beyond about 48 hours the wind model falls back from HRDPS to a coarser global one that doesn't resolve funnelling between the islands. The page tells you which it used.
  • Wave heights are calculated, not measured. A model of a model.
  • Nothing here knows about fog, and fog is what most often catches an open boat with no radar on an August morning. Read the visibility line in the official forecast.
What changed, and why

Five updates. The old code for anything risky is kept in comments inside the <script> block, so any of it can be put back by hand.

1. Currents no longer read too strong on quiet days. The page used to fetch a single day of tide, then treat that day's biggest current as full strength. So a weak neap tide got described exactly like a big spring tide. It now pulls eight days and judges the day against that range. Slack times have not moved — only the strength, and it will read lower on small-tide days. Expect fewer "wind is fighting the tide" flags, and for the ones that remain to mean more.

2. Warnings stop at 48 hours. An Environment Canada warning describes the next day or two, but nothing in the data says which days it covers. Previously a warning in effect today would colour a trip you were planning for next week. Now:

  • Inside 48 hours — the warning applies exactly as before.
  • Beyond 48 hours — warnings are not read, not listed and not applied. You get one plain message saying so, and nothing else about them.
  • Beyond 48 hours, if no official wind figure applies either, the verdict is marked unverified. Model output only, with nothing checking it. Fine for spotting a promising day; not something to commit to.

The bulletin also no longer reaches past about five days. Day names repeat weekly, so "Thursday" in the extended forecast was matching a Thursday eight days out.

3. Times are half-hour slots. Leave-at and back-by are dropdowns now rather than free entry, because the forecast is hourly and offering 5:17 would misrepresent the resolution. Pick any :00 or :30 between 5 am and 9:30 pm, or leave both blank for best windows. A half-hour still has to land on a whole one to be graded, so your departure rounds down and your return rounds up — both toward the longer, more exposed day. A 5:30 pm return is graded against 6 pm rather than 5. The plan panel tells you when it has done this and which hours it actually used.

4. Weather across the route. Average air temperature, the range, what the sky is doing, rain, and visibility hour by hour. With a plan entered it covers your window; without one, the whole day. This data was already being downloaded for every leg and hour — it was only being read to spot thunderstorms, and thrown away otherwise. Note it is air temperature. The water stays around 10–12 °C all summer.

5. Two small fixes. The "try again now" link on a stale bulletin was clearing a cache key that didn't exist, so it never actually cleared anything — it only appeared to work because the staleness check re-fetched anyway. It now clears the real keys. Caching itself is deliberate and unchanged: weather.gc.ca is often unreachable, and a stored bulletin with an age warning on it beats no bulletin at all. The manual Forecast wind box is untouched and remains the fallback when nothing loads. Separately, a leftover from an old rename and a piece of text being cleaned twice were tidied up; neither changed what you see.

Worth checking once it's live. Pick a small-tide day and see whether the wind-against-tide flags have thinned out. If they've gone quiet on days that genuinely felt fine on the water, that's the first change doing its job. And keep the log — what the page said against how the boat actually felt. A season of that beats every default in this file.
